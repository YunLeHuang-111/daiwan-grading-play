# 手寫分數 CNN 人工驗收

## 執行方式

1. 在專案根目錄執行 `python -m http.server 8080 --bind 127.0.0.1`。
2. 開啟 `http://127.0.0.1:8080/`，確認顯示「CNN 可用」。
3. 玩家寫完整總分 `0、10、20…100`；確認練習模式立即辨識，單科／多科延後到倒數結束。

## 驗收清單

- [ ] 沒有「辨識分數」、「確認使用」或手動分數按鈕。
- [ ] 右上角辨識框沒有邊框、底色或文字，考卷排版未被撐開。
- [ ] 透明 ROI 固定貼齊學生卷右上角，尺寸為考卷寬 32%、高 20%。
- [ ] 寫 `10`：前兩位都執行 CNN，最後向下取到 10 分。
- [ ] 寫 `60`：即使個位誤認為其他數字，最後仍依十位得到 60 分。
- [ ] 寫 `100`：辨識前兩位，並以三段且第一位為 `1` 的特例得到 100 分。
- [ ] 將 `100` 三個數字寫得較緊，仍應切成三段並得到 100 分。
- [ ] `30、70、80、90` 在十位 TTA 至少四票一致時可完成辨識。
- [ ] 十位 TTA 只有三票或更少時仍顯示低信心，不強制猜分。
- [ ] `20`～`90` 被多切出第三段時，仍依前兩個辨識數字向下取到十位。
- [ ] 空白、單寫 `6`、兩字元開頭為 `0` 或超過三個有效字元時拒絕交卷。
- [ ] 單科／多科按「下一張」只保存 ROI 並換卷，分數保持空白。
- [ ] 單科／多科倒數結束後才逐張統一辨識並結算。
- [ ] 批次低信心或空白項目顯示「辨識失敗」，不套用假分數。
- [ ] 練習模式失敗時顯示明確階段，不只顯示籠統的「辨識失敗」。
- [ ] 十位低信心原因包含候選數字、平均信心、TTA 票數與機率差。
- [ ] 單科／多科結算卡片逐張顯示各自的失敗原因。
- [ ] Browser Console 的 `[score-recognition]` 診斷包含相同考卷編號與結構化資訊。
- [ ] 半透明抗鋸齒筆畫在正規化後仍保留灰階，不會全部硬切成 0／1。
- [ ] 預設切割失敗時，診斷中的 `candidateAttempts` 至少列出兩種策略。
- [ ] 替代切割成功時，`chosenStrategy` 顯示實際採用的策略並完成給分。
- [ ] 預設切割成功時只執行一個候選，不產生不必要的額外 CNN 推論。
- [ ] 灰階低信心時自動增加 `default/binary` 嘗試。
- [ ] 灰階成功時不執行二值或其他切割候選。
- [ ] `10、80、90、100` 可在灰階不穩定時由二值輪廓接手。
- [ ] 練習模式的「檢查目前練習考卷分數」只顯示結果，不增加交卷張數。
- [ ] 練習模式按「下一張」會重新辨識並正式交卷。
- [ ] 修改筆跡、復原、橡皮擦、清除與重寫會清除舊辨識結果。
- [ ] 已批改考卷縮圖與放大頁保留右上角完整分數筆跡。
- [ ] 模型載入失敗時不產生模擬分數，也沒有手動備援。
- [ ] 手機／平板版面可完整寫下 `100`。

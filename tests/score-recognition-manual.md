# 手寫分數 CNN 人工驗收紀錄

## 執行方式

1. 在專案根目錄執行 `python -m http.server 8080`。
2. 開啟 `http://localhost:8080/`，確認 Console 無例外且顯示「CNN 可用」。
3. 分別用桌面滑鼠、Chrome 行動裝置模擬與可用的實體觸控裝置測試。

## 驗收清單

- [ ] 桌面 Chrome：10、50、100 均走「書寫 → 辨識 → 確認 → 下一張」。
- [ ] 行動尺寸：ROI 沒有被 CSS scale 裁切，100 三位數可完整書寫。
- [ ] 只在題目區畫圈：回報分數區空白，不產生候選分數。
- [ ] 辨識 80 後擦除並改寫 90：舊候選與已確認分數失效。
- [ ] 「重新寫分數」只移除 ROI 筆跡，題目區紅筆仍保留。
- [ ] 0 可提交；85、110、空白與小墨點不會自動確認。
- [ ] 模型或 CDN 被阻擋時，按鈕輸入仍可完成一局。
- [ ] 單科、多科、練習模式仍可切卷、計時與結算。
- [ ] 已批改縮圖與放大頁保留右上角紅筆分數。
- [ ] DPR 1／2／3、橫直向重排後 ROI 擷取位置正確。

> 自動化測試不等同真實書寫準確率。完整分數字串正確率、100 正確率、拒辨率與高信心誤判率，必須以多位書寫者的獨立測試集另行量測，不以 MNIST 單字元 1.1% top-1 error 代替。

## 2026-11-13 實際執行紀錄

環境：Codex in-app Chromium browser、本機 Node 靜態伺服器、桌面預設 viewport 與 390×844 行動 viewport。

- 通過：ONNX Runtime Web 與本機 `mnist-12.onnx` 載入，UI 顯示「CNN 可用」，Console 0 error／warning。
- 通過：未書寫時按辨識，顯示「分數區沒有足夠筆跡」，不產生候選、不開放交卷，並展開手動備援。
- 通過：手動選 50 分後可交卷；新卷會清除分數與來源，既有練習模式切科流程正常。
- 通過：用瀏覽器指標在 ROI 畫橢圓 `0`，真實 CNN 回傳 0 分候選；確認後 `score-preview=0`、來源為「CNN 辨識・已確認」，可提交。
- 通過：結果頁顯示 2 張考卷，含 CNN 交卷；DOM 中有一個 `.review-ink`，右上角手寫筆跡保留。
- 通過：390×844 手機版套用 `.phone-layout`；ROI 實測 118×52 CSS px、左右界 246.2～364.2，未超出 390 px viewport。
- 安全拒辨：以直線畫出的方形 `10` 被逐字模型讀為原始 `12`；因字串非法而拒絕確認，沒有四捨五入或偷改成合法分數。
- 尚未執行：實體手機／Apple Pencil、DPR 2／3 實機，以及多位書寫者量化準確率資料集。
